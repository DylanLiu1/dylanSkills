1. 简介

1.1 业务目标

本库存系统旨在构建一套分层架构的企业级库存管理体系，采用"三层库存架构"模式，实现全渠道库存共享、防超卖机制和库存精准调度。通过统一的库存中枢管理，打通线上线下销售渠道与物理仓库之间的数据链路，保障库存数据的实时性、准确性和一致性，支撑智能分仓、就近发货等业务策略，最终提升库存周转效率、降低运营成本、改善客户体验。

1.2 项目背景

随着业务规模扩张和全渠道销售战略的推进，现有库存管理模式面临以下核心挑战：

  • 多渠道库存分散管理，无法实现全局库存共享与统一调度，易出现部分渠道超卖、部分渠道库存积压的现象
  • 销售端与仓储端库存数据不同步，实物库存与系统账面存在差异，导致订单履约风险
  • 缺乏在途库存、预占库存等多维度库存状态管理，无法支撑精细化库存运营
  • 跨系统集成能力薄弱，ERP、OMS、TMS等系统间数据协同效率低下

为解决上述问题，启动新一代库存系统建设项目，采用分层架构设计理念，构建销售层、调度层、仓库层三级库存体系，配套完整的技术分层架构，支撑企业未来3-5年的业务发展需求。

2. 范围

✓ In Scope（范围内）

  • 销售层：渠道库存分配、预占释放、活动库存预留、实时可售库存查询
  • 调度层：全局库存汇总、在途库存管理、可用实物库存管理、销售预占库存管理、智能分仓策略
  • 仓库层：WMS系统对接、货主管理、批号管理、库位管理、库存状态管理、入库/拣货/出库作业驱动
  • 展示层：Web管理端、PDA手持操作终端、移动端小程序
  • 业务层：入库、出库、调拨、盘点、预警等核心业务逻辑及规则引擎
  • 数据层：库存单据、SKU主数据、操作日志的存储与管理
  • 集成层：ERP系统对接、OMS订单系统对接、TMS运输系统对接
  • 全渠道库存共享机制与防超卖控制

✗ Out of Scope（范围外）

  • 采购管理与供应商管理功能（属ERP系统范畴）
  • 财务核算与成本管理（属财务系统范畴）
  • 订单履约全流程管理（属OMS系统范畴）
  • 运输配送路径优化（属TMS系统范畴）
  • 商品主数据全生命周期管理（属MDM系统范畴）
  • 线下门店POS收银功能
  • 仓储自动化设备（AGV、分拣机等）的直接控制
  • 第三方电商平台店铺运营管理
3. 总体架构

3.1 架构描述

本库存系统采用分层设计理念，从业务逻辑维度划分为销售层、调度层、仓库层三层库存架构，实现全渠道库存共享与精准调度；从技术实现维度划分为展示层、业务层、数据层、集成层四层技术架构，保障系统的可扩展性与可维护性。

业务三层架构自上而下形成"销售可售库存-调度中心库存-仓库实物库存"的三级库存体系，通过库存预占、实时同步、状态联动等机制，确保各层级库存数据的一致性，从源头避免超卖问题，同时支撑"一盘货"全局调度策略。

4. 业务流程

4.1 核心业务流程描述

库存系统核心业务流程围绕"订单扣减-库存预占-仓储作业-实物出库"的主线展开，贯穿销售层、调度层、仓库层三个层级，确保每一笔库存变动都有迹可循、账实一致。主要流程包括：

  • 库存查询与预占流程：销售渠道发起可售库存查询，销售层基于调度层同步的可用库存计算可售量；订单创建时触发库存预占，扣减对应渠道的可售库存，同时在调度层增加预占库存标记。
  • 出库履约流程：订单审核通过后，调度层根据智能分仓策略指定发货仓库，向仓库层WMS下发出库指令；WMS执行拣货、复核、出库作业后，回传出库确认，调度层扣减实物库存并释放预占。
  • 入库作业流程：采购到货或退货入库时，WMS执行收货、质检、上架作业，完成后同步至调度层增加可用库存；调度层更新全局库存数据，并同步至销售层释放对应可售库存。
  • 库存调拨流程：根据库存分布与销售预测，调度层发起仓库间调拨指令，调出仓库执行出库，调入仓库执行入库，在途库存全程跟踪，到货后转为可用库存。
  • 库存盘点流程：定期或不定期发起盘点任务，WMS执行实物盘点，产生盘盈盘亏差异，经审批后调整系统库存，确保账实相符。

5. 功能模块详细规格

5.1 销售层模块

5.1.1 渠道库存分配管理

管理各销售渠道的库存配额，支持按比例分配、固定配额、动态分配等多种策略，保障重点渠道库存供给。
输入：渠道编码、SKU编码、分配数量、分配策略、生效时间
输出：渠道库存配额结果、分配日志
业务规则：
  • 分配总量不得超过调度层可用库存上限
  • 支持按日/周/月维度设置分配周期
  • 渠道间库存可人工调剂，需记录审批痕迹

5.1.2 库存预占与释放

订单创建时预占对应渠道库存，订单取消/超时未支付时自动释放库存，防止超卖。
输入：订单号、SKU编码、预占数量、渠道编码、预占有效期
输出：预占结果（成功/失败）、预占流水号
业务规则：
  • 可售库存不足时，预占失败并返回具体缺口数量
  • 预占超时未确认自动释放，超时时间可配置
  • 支持批量预占与批量释放

5.1.3 活动库存预留

针对大促、秒杀等营销活动，单独预留活动专属库存，与常规渠道库存隔离管理。
输入：活动ID、SKU编码、预留数量、活动时间段
输出：活动库存池、预留确认单
业务规则：
  • 活动库存从对应渠道总配额中扣除
  • 活动结束后未售完库存自动回流渠道可用库存
  • 支持活动级别的超卖控制参数配置

5.1.4 实时可售库存查询

为前端销售平台提供毫秒级可售库存查询服务，支持单查、批量查、分页查。
输入：SKU编码列表、渠道编码、仓库范围（可选）
输出：各SKU可售库存数量、预计发货仓库
业务规则：
  • 查询结果包含可用库存与预占中库存明细
  • 高并发场景下支持降级返回近似值
  • 查询响应时间需满足性能指标要求

5.2 调度层模块

5.2.1 全局库存汇总

汇总各仓库、各状态的库存数据，形成全局库存视图，作为库存调度与决策的依据。
输入：各仓库库存数据、在途单据数据
输出：全局库存汇总表、库存分布视图
业务规则：
  • 按SKU+仓库+状态维度汇总库存数量
  • 支持按货主、批号、效期等维度下钻
  • 数据实时同步，延迟不超过设定阈值

5.2.2 在途库存管理

管理采购在途、调拨在途、退货在途等各类在途库存，全程跟踪物流状态。
输入：在途单据号、SKU、数量、预计到货时间、运输单号
输出：在途库存台账、预计到货预告
业务规则：
  • 在途库存计入可用库存的比例可配置
  • 支持在途异常预警与跟催
  • 到货入库后自动核销在途库存

5.2.3 智能分仓策略

根据订单收货地址、各仓库存情况、配送时效等因素，自动选择最优发货仓库。
输入：收货地址、SKU清单、订单类型、时效要求
输出：推荐发货仓库、分仓结果明细
业务规则：
  • 优先匹配有库存且距离最近的仓库
  • 支持按区域、渠道、客户等级配置分仓优先级
  • 单仓不足时支持拆单分仓发货

5.2.4 库存调拨管理

发起仓库间的库存调拨，平衡各仓库存分布，支撑全局库存优化。
输入：调出仓、调入仓、SKU清单、调拨数量、调拨原因
输出：调拨单、在途库存记录、入库核销单
业务规则：
  • 调拨出库后库存转为在途状态
  • 调入入库后核销在途并增加可用库存
  • 支持调拨差异处理与损耗记录

5.3 仓库层模块

5.3.1 入库作业管理

驱动WMS执行采购入库、调拨入库、退货入库等各类入库作业，确保实物准确上架。
输入：入库通知单、货主信息、SKU明细、批号/效期
输出：入库确认单、库位分配结果、上架记录
业务规则：
  • 支持收货、质检、上架三步入库流程
  • 批号、效期、序列号等属性必须准确采集
  • 入库差异需登记并走审批流程

5.3.2 出库拣货管理

根据出库指令生成拣货任务，驱动仓内拣货、复核、打包、发货全流程。
输入：出库指令、波次规则、拣货策略
输出：拣货单、出库确认、打包明细
业务规则：
  • 支持按波次汇总拣货，提升作业效率
  • 先进先出（FIFO）、近效期先出等策略可选
  • 出库复核确保实物与单据一致

5.3.3 库位与状态管理

管理仓库内货位精细化库存，记录库存状态（可用、冻结、质检、残次等）。
输入：库位编码、SKU、数量、库存状态、操作类型
输出：库位库存台账、状态变更记录
业务规则：
  • 库存状态变更需有明确的业务单据支撑
  • 冻结库存不计入可用库存
  • 支持库位间移库作业

5.3.4 库存盘点管理

支持周期盘点、循环盘点、异动盘点等多种盘点方式，确保账实一致。
输入：盘点范围、盘点方式、盘点人
输出：盘点单、差异报表、盘盈盘亏调整单
业务规则：
  • 盘点期间对应库存冻结，禁止出入库
  • 差异需经审批后方可调整系统库存
  • 支持盲盘、明盘两种盘点模式

5.4 业务层公共模块

5.4.1 规则引擎

提供可配置的业务规则引擎，支持库存分配规则、分仓规则、预警规则等灵活配置。
输入：规则条件、规则动作、优先级
输出：规则配置结果、规则执行日志
业务规则：
  • 规则支持版本管理与灰度发布
  • 规则执行异常不影响主流程，支持降级
  • 规则变更需审批并记录操作日志

5.4.2 库存预警

基于库存阈值、效期、周转率等指标，自动触发库存预警通知。
输入：预警指标、阈值配置、通知对象
输出：预警消息、预警报表
业务规则：
  • 支持库存上下限、效期预警、呆滞库存预警
  • 预警级别分高/中/低三级，对应不同通知方式
  • 同一预警去重，避免重复告警

7. 异常与错误处理

系统针对各类业务异常与技术异常设计统一的处理机制，确保异常可感知、可追溯、可恢复。

7.1 业务异常处理

  • BIZ-001 库存不足异常

    处理方式：预占或扣减时可用库存不足，立即返回失败并提示具体缺口数量；不允许负库存操作；触发库存不足预警。

  • BIZ-002 重复预占异常

    处理方式：基于订单号做幂等校验，同一订单重复预占直接返回首次预占结果，不重复扣减库存。

  • BIZ-003 库存状态非法

    处理方式：操作目标库存状态不允许当前操作（如已冻结库存执行出库），拒绝操作并返回具体状态说明。

  • BIZ-004 批次/效期不存在

    处理方式：指定的批号或效期在仓库中不存在，拒绝操作并提示核对批次信息。

  • BIZ-005 调拨在途未核销

    处理方式：调入仓已入库但调出仓未出库确认，触发异常对账流程，人工介入核查。

7.2 技术异常处理

  • SYS-001 接口超时异常

    处理方式：设置合理超时时间，超时后自动重试（查询类可重试，交易类需基于幂等键重试）；超过重试次数返回系统繁忙，触发告警。

  • SYS-002 缓存击穿/雪崩

    处理方式：采用多级缓存架构，设置热点数据永不过期，使用互斥锁或队列防止缓存击穿，降级时返回数据库准实时数据。

  • SYS-003 消息消费失败

    处理方式：消息消费失败自动重试，达到最大重试次数后进入死信队列，告警通知人工处理；保证消息不丢失。

  • SYS-004 数据库连接异常

    处理方式：连接池监控，异常时快速失败并触发告警；核心流程支持读写分离与主备切换。

7.3 数据一致性保障

库存数据一致性通过以下机制保障：

  • 乐观锁机制：库存扣减采用版本号乐观锁，防止并发超卖
  • 事务补偿：跨系统操作失败时，通过补偿机制回滚已执行步骤
  • 定时对账：日终进行销售层-调度层-仓库层三级库存对账，差异自动预警
  • 操作留痕：所有库存变动记录完整操作日志，支持全链路追溯
8. 非功能需求（NFR）

8.1 性能需求

  • 可售库存查询：单SKU查询响应时间 ≤ 50ms，批量查询（100个）≤ 200ms
  • 库存预占接口：平均响应时间 ≤ 100ms，99分位 ≤ 300ms
  • 系统支持峰值QPS ≥ 5000，大促期间可弹性扩容
  • 日终批量对账处理时长 ≤ 30分钟
  • 库存数据同步延迟：调度层到销售层 ≤ 1s，仓库层到调度层 ≤ 5s

8.2 安全需求

  • 所有接口需鉴权认证，禁止匿名访问
  • 库存调整等关键操作需双人复核与审批留痕
  • 操作日志完整记录操作人、时间、IP、操作内容，不可篡改
  • 数据传输全程加密，敏感数据脱敏展示
  • 支持按角色、仓库、货主维度的数据权限隔离
  • 满足等保三级合规要求

8.3 可用性需求

  • 系统全年可用率 ≥ 99.9%
  • 核心查询服务支持降级运行，保障基本销售业务不受影响
  • 支持灰度发布与不停机升级
  • 故障恢复时间（RTO）≤ 30分钟
  • 数据恢复点目标（RPO）≤ 5分钟
  • 提供7×24小时监控告警

8.4 可运维需求

  • 提供统一监控大盘，实时展示库存关键指标与系统健康度
  • 支持全链路追踪，可快速定位问题节点
  • 提供库存对账工具与数据修复工具
  • 支持容器化部署与弹性伸缩
  • 关键配置支持热更新，无需重启服务
  • 日志标准化输出，支持集中采集与检索

8.5 可扩展性

  • 支持多货主、多仓库、多渠道的横向扩展
  • 业务规则可配置，新增业务场景尽量无需代码开发
  • 接口设计标准化，便于新渠道、新系统快速接入
  • 数据层支持分库分表，支撑亿级数据量

8.6 数据准确性

  • 系统库存数据准确率 ≥ 99.95%
  • 三级库存数据一致性误差率 ≤ 0.05%
  • 库存盘点差异率 ≤ 0.1%（按金额计算）
  • 关键操作数据零丢失
9. 依赖与约束

9.1 系统依赖

依赖系统 依赖类型 依赖内容 责任方
ERP系统 强依赖 SKU主数据、货主数据、仓库数据、采购入库单、财务核算数据 待补充
OMS订单系统 强依赖 订单数据、订单状态变更、取消/退款通知 待补充
WMS仓储管理系统 强依赖 仓储作业执行、实物库存数据、出入库回执 待补充
TMS运输管理系统 弱依赖 调拨物流状态、配送在途跟踪 待补充
统一身份认证平台 强依赖 用户认证、权限管理、单点登录 待补充
消息中间件 强依赖 系统间异步通信、解耦与流量削峰 基础架构部
缓存系统（Redis） 强依赖 实时库存缓存、热点数据加速 基础架构部

9.2 业务约束

  • 库存操作必须有对应的业务单据支撑，禁止无凭无据的库存调整
  • 负库存禁止出库，特殊场景需经特批并记录备案
  • 库存成本核算遵循财务制度，由ERP统一负责，本系统不涉及成本计算
  • 各渠道库存分配策略需符合公司整体销售政策与渠道管理规范
  • 盘点差异调整需经财务确认后方可执行

9.3 技术约束

  • 遵循企业统一技术栈规范，采用公司指定的开发语言与中间件
  • 数据存储使用公司统一数据库资源，遵循数据安全管理规范
  • 接口规范遵循企业服务总线（ESB）接入标准
  • 部署架构需符合企业云原生平台规范
  • 日志与监控接入公司统一监控平台
